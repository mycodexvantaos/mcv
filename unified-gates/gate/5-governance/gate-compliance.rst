================
Gate Compliance
================

:Version: 1.0.0
:Status: normative

Compliance Framework
--------------------

Gate compliance ensures that the gate system itself adheres to the platform
governance standards. Compliance is validated by ``gate-98-compliance-report-validation``
at the ``l90`` layer on every production promotion.

Compliance Dimensions
---------------------

**Catalog Completeness**: All gates referenced in ``gate-catalog.yaml`` MUST have
corresponding definition files. No orphaned catalog entries are permitted.

**Schema Conformance**: All gate definitions MUST pass JSON Schema validation
against ``schemas/ai-infra-gate.schema.json``.

**Lifecycle Compliance**: No gate in ``destroyed`` lifecycle may be referenced
as a dependency or included in a pipeline.

**Evidence Chain Integrity**: The audit evidence chain MUST have zero gaps or
hash mismatches.

**Owner Registry Completeness**: Every gate MUST have a registered owner.
Gates without owners are treated as compliance violations.

**Waiver Compliance**: All active waivers MUST be within their approved duration.
Expired waivers MUST be renewed or the gate failure MUST be remediated.

Compliance Report
-----------------

The compliance report is generated by ``scripts/generate-gate-report.py`` and
stored in ``outputs/gate-audit-report.json``. It is required for every production
promotion and MUST be signed by the platform governance council.
