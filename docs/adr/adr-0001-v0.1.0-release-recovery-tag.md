# ADR 0001: v0.1.0 Release Recovery Tag

**Date**: 2026-05-19
**Status**: Superseded by ADR-006
**Context**: GitHub Release Immutability Record (GH013) blocks original tag name

## Context

The official `v0.1.0` release tag is blocked by GitHub's Immutability Record (GH013), an internal database record that persists even after releases are deleted and the "Enable release immutability" setting is disabled. This record locks the exact tag name `v0.1.0`, preventing any recreation of the tag or release.

## Original Decision (Superseded)

Originally proposed using `v0.1.0.0` as the fallback publication tag. However, after deleting the `v0.1.0.0` release and tag via `gh release delete --yes --cleanup-tag`, attempting to recreate `v0.1.0.0` at the correct commit fails with GH013. Additionally, the existing `v0.1.0.0` tag points to the wrong commit (`e35af2a` instead of `1371a89`), making it unsuitable as a recovery tag.

## Updated Decision (ADR-006)

Per ADR-006, the fallback publication tag has been changed to `v0.1.0-stable`, which was successfully created at commit `1371a8966c3047bbd95e87308a0bc81e6b72bb41` with a GitHub Release containing all 7 artifacts.

## Consequences

- **Positive**: Release publication is unblocked via `v0.1.0-stable`.
- **Negative**: Original fallback tag `v0.1.0.0` is blocked by GH013 and points to wrong commit.
- **Mitigation**: Use `v0.1.0-stable` as documented in ADR-006.
