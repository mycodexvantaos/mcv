## Summary

MyCodeXvantaOS v0.1.0 is the first stable release of the platform. It delivers a fully auditable governance enforcement layer, a reproducible release pipeline with supply-chain artifacts, and a validated self-hosted deployment path. This release is the culmination of four major milestones: platform governance enforcement, release candidate stabilization, release validation and packaging, and RC soak and stable promotion readiness.

The release candidate v0.1.0-rc.1 was subjected to comprehensive soak validation (19 checks, 19 passed, 0 failed) and promotion gate evaluation (9 of 11 gates passed, 2 skipped with documented acceptable-skip classifications for RC). Based on this evidence, the RC is promoted to stable with documented conditions for signing and infrastructure.

## Major Milestones

### Platform Governance Enforcement (PR #57–#62)

- **Audit enforcement** (PR #57): The API wraps all mutating routes with `withAudit()`, generating traceable audit events with unique `trace_id` values. The audit chain integrity endpoint (`GET /v1/audit/verify`) enables downstream verification.
- **Knowledge trace enforcement** (PR #58, #60): Knowledge-assisted answers must carry a valid retrieval receipt. The `knowledgeTraceEnforcementMiddleware` flag and receipt validation logic ensure that knowledge claims are traceable to their source retrieval operations.
- **Dream safety lifecycle** (PR #59, #61): Dream run results require explicit review before application. The `dreamSafetyEnforcementMiddleware` flag, combined with `withPolicy()` middleware, enforces a review gate, before/after JSON tracking, rollback capability, and a prohibition on delete operations in MVP.
- **Release artifact manifest** (PR #62): A release manifest generator produces `release/release-manifest.json` with version, commit, runtime metadata, services list, governance flags, and a manifest hash for integrity verification.

### Release Candidate Stabilization (PR #63–#65)

- **CodeQL consolidation** (PR #63): Three redundant CodeQL analysis paths were consolidated into a single CodeQL Advanced workflow (v4 actions) covering actions, javascript-typescript, and python. The legacy `codeql-analysis.yml` was removed, and the duplicate CodeQL job was removed from `security-scan.yaml`.
- **Terraform Cloud documentation** (PR #63): An external Terraform Cloud GitHub App reports a failing status check (`stc-*`) on every commit. Since no Terraform files exist in the repository, this failure is classified as `infrastructure-not-configured` and documented in the `terraform-cloud-guard.yaml` workflow.
- **Governance flag reporting** (PR #64): The governance check now includes a `policyRuntimeEnforcement` check (24 total checks) and a structured Enforcement Flag Summary listing all 7 canonical enforcement flags grouped by category.
- **Release candidate verification** (PR #65): A new `pnpm rc:verify` script and `.github/workflows/release-candidate-check.yml` workflow provide comprehensive RC readiness verification covering governance, contracts, policy, tests, manifest, docker, python, and infrastructure categories.

### Release Validation and Packaging (PR #66–#70)

- **Release artifact generation** (PR #66): `pnpm release:artifacts` generates release-manifest.json, artifact-digests.json, and verification-summary.json with SHA3-512 primary and SHA-256 secondary governance hashes.
- **SBOM generation** (PR #67): `pnpm release:sbom` produces a CycloneDX 1.5 JSON SBOM with component inventory and dependency tracking.
- **Provenance generation** (PR #68): `pnpm release:provenance` produces an in-toto Statement v1 with SLSA v1 predicate and supply-chain-summary.json. Unsigned provenance is classified as `signing-not-configured`.
- **Self-hosted quickstart** (PR #69): A quickstart guide and smoke test script for self-hosted deployment validation.
- **Release promotion policy** (PR #70): Defines 11 promotion gates (G001–G011) with RC and stable status, verification methods, and required artifacts.

### RC Soak and Stable Promotion Readiness (PR #71–#74)

- **RC soak validation** (PR #71): `pnpm rc:soak` executes comprehensive soak validation and produces soak-report.json and markdown report. 19/19 checks passed, 6 skipped with documented classifications.
- **Promotion gate evaluation** (PR #72): `pnpm release:promotion:evaluate` evaluates all 11 promotion gates and produces promotion-evaluation.json and markdown report. Recommendation: conditional-go (9 passed, 0 failed, 2 acceptable-skip).
- **Stable release signing plan** (PR #73): Defines signing methods (Sigstore keyless, GPG, Vault/HSM), classifications, and implementation phases. Machine-readable `signing-policy.json` governs signing requirements per release type.
- **Stable release draft** (PR #74): This document and the accompanying release-draft.json constitute the v0.1.0 stable release package.

### Documentation Synchronization (PR #75–#76)

- **README and architecture sync** (PR #75): Synchronized README.md and PLATFORM_ARCHITECTURE.md with the v0.1.0 stable codebase, resolving 9 documentation drift issues: Node 20 to 22, npm to pnpm 9, port 3000 to 9100, /health to /v1/\* endpoints, 3 to 5 apps, missing directories (python/, release/, providers/, runtimes/local/), contract counts (15 services, 14 schemas, 7 events, 16 resource-kinds, 5 policies), governance and release commands, and SHA-256 to SHA3-512 primary governance hash. Added the nine-layer hexagonal architecture (Layers A-I), dual-plane architecture section, and 49 CI workflows documentation.
- **CONTRIBUTING.md rewrite** (PR #76): Complete rewrite of CONTRIBUTING.md to reflect the current nine-layer hexagonal architecture, dual-plane architecture, pnpm 9 commands, Node.js 22+ requirement, port 9100, governance and release pipeline commands, Python intelligence plane commands, and an updated PR checklist with governance checks (governance:check, contracts:validate, no-section-sign) and architecture compliance requirements.

## Known Limitations

- **Artifact signing**: Provenance artifacts at initial publication are unsigned (`signing-not-configured`). The Sigstore keyless signing workflow is now configured at `.github/workflows/sign-release.yaml` (Issue #77). Trigger the workflow via `workflow_dispatch` with `version=v0.1.0` to sign existing provenance artifacts. Once signed, G010 transitions to `signing-configured`. See `docs/security/release-signing.md` for verification instructions.
- **Terraform Cloud external status**: The external Terraform Cloud GitHub App may report a failing status check (`Terraform Cloud/mycodexvantaos/stc-*`) on every commit. This is classified as `infrastructure-not-configured` because no Terraform files exist in the repository.
- **Kubernetes deployment**: Requires `KUBE_CONFIG_DEV` secret. When absent, deployment is classified as `infrastructure-not-configured` and skipped. See `docs/deployment/infrastructure-secrets.md` for configuration instructions (Issue #78).
- **Cloudflare deployment**: Requires `CF_API_TOKEN` secret. When absent, deployment is classified as `infrastructure-not-configured` and skipped. See `docs/deployment/infrastructure-secrets.md` for configuration instructions (Issue #78).
- **Python tests**: May have environment-specific failures. Python CI is non-blocking for release readiness.

## Upgrade Path

This is the first stable release. There is no prior stable version to upgrade from. To adopt this release:

1. Clone the repository at tag `v0.1.0-stable`
2. Run `pnpm install --frozen-lockfile`
3. Run `pnpm rc:verify` to validate readiness
4. Build the Docker image: `docker build -t mycodexvantaos:v0.1.0 .`
5. Run the smoke test: `./scripts/smoke/docker-smoke.sh mycodexvantaos:v0.1.0`
6. Start the API: `docker run -p 9100:9100 mycodexvantaos:v0.1.0`
7. Validate endpoints: `GET /v1/health`, `GET /v1/version`, `GET /v1/runtime`

For upgrading from v0.1.0-rc.1:

1. Update the git reference from `v0.1.0-rc.1` to `v0.1.0-stable`
2. No database migrations are required (schema unchanged from RC)
3. No configuration changes are required
4. Verify governance enforcement flags are unchanged (7 flags, same values)
