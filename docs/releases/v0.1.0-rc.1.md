## Summary

This is the first release candidate for MyCodeXvantaOS v0.1.0. It represents the culmination of two major milestones: **platform-governance-enforcement** and **release-candidate-stabilization**. The codebase now has a fully auditable governance enforcement layer, consolidated security scanning, and a reproducible release candidate verification pipeline.

This release candidate is intended for validation, self-hosted testing, and audit review. It is not yet designated as stable.

---

## Major Milestones

### Platform Governance Enforcement (PR #57–#62)

- **Audit enforcement** (PR #57): The API now wraps all mutating routes with `withAudit()`, generating traceable audit events with unique `trace_id` values. The audit chain integrity endpoint (`GET /v1/audit/verify`) enables downstream verification.
- **Knowledge trace enforcement** (PR #58, #60): Knowledge-assisted answers must carry a valid retrieval receipt. The `knowledgeTraceEnforcementMiddleware` flag and receipt validation logic ensure that knowledge claims are traceable to their source retrieval operations.
- **Dream safety lifecycle** (PR #59, #61): Dream run results require explicit review before application. The `dreamSafetyEnforcementMiddleware` flag, combined with `withPolicy()` middleware, enforces a review gate, before/after JSON tracking, rollback capability, and a prohibition on delete operations in MVP.
- **Release artifact manifest** (PR #62): A release manifest generator produces `release/release-manifest.json` with version, commit, runtime metadata, services list, governance flags, and a manifest hash for integrity verification.

### Release Candidate Stabilization (PR #63–#65)

- **CodeQL consolidation** (PR #63): Three redundant CodeQL analysis paths were consolidated into a single CodeQL Advanced workflow (v4 actions) covering actions, javascript-typescript, and python. The legacy `codeql-analysis.yml` was removed, and the duplicate CodeQL job was removed from `security-scan.yaml`.
- **Terraform Cloud documentation** (PR #63): An external Terraform Cloud GitHub App reports a failing status check (`stc-*`) on every commit. Since no Terraform files exist in the repository, this failure is classified as `infrastructure-not-configured` and documented in the `terraform-cloud-guard.yaml` workflow.
- **Governance flag reporting** (PR #64): The governance check now includes a `policyRuntimeEnforcement` check (24 total checks) and a structured Enforcement Flag Summary listing all 7 canonical enforcement flags grouped by category.
- **Release candidate verification** (PR #65): A new `pnpm rc:verify` script and `.github/workflows/release-candidate-check.yml` workflow provide comprehensive RC readiness verification covering governance, contracts, policy, tests, manifest, docker, python, and infrastructure categories.

## Known Limitations

- **Terraform Cloud external status**: The external Terraform Cloud GitHub App may report a failing status check (`Terraform Cloud/mycodexvantaos/stc-*`) on every commit. This is classified as `infrastructure-not-configured` because no Terraform files exist in the repository. Resolution requires reconfiguration in the Terraform Cloud console or GitHub App settings.
- **Kubernetes deployment**: Requires `KUBE_CONFIG_DEV` secret. When absent, deployment is classified as `infrastructure-not-configured` and skipped.
- **Cloudflare deployment**: Requires `CF_API_TOKEN` secret. When absent, deployment is classified as `infrastructure-not-configured` and skipped.
- **Python tests**: May have environment-specific failures. Python CI is non-blocking for RC readiness.
- **Artifact signing**: Not yet configured for this RC. Classified as `signing-not-configured`. Stable release must define signing requirements.

## Upgrade Path

This is the first release candidate. There is no prior version to upgrade from. To adopt this release candidate:

1. Clone the repository at tag `v0.1.0-rc.1`
2. Run `pnpm install --frozen-lockfile`
3. Run `pnpm rc:verify` to validate readiness
4. Build the Docker image: `docker build -t mycodexvantaos:v0.1.0-rc.1 .`
5. Run the smoke test: `./scripts/smoke/docker-smoke.sh mycodexvantaos:v0.1.0-rc.1`
6. Start the API: `docker run -p 9100:9100 mycodexvantaos:v0.1.0-rc.1`
7. Validate endpoints: `GET /v1/health`, `GET /v1/version`, `GET /v1/runtime`

For this RC to be promoted to a stable release (v0.1.0), the following must be satisfied:

- All GitHub Actions workflows pass on main
- `pnpm rc:verify` passes with zero failures
- Release artifacts (manifest, digests, SBOM, provenance) are generated and published
- Self-hosted quickstart validation passes
- Release promotion gate policy is satisfied
- No critical security scan failures (CodeQL, Gitleaks, Semgrep)
- Known infrastructure skips are documented
- Artifact signing is defined (or explicitly deferred with documented rationale)
